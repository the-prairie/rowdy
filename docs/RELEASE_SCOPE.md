# Rowdy 0.6 scope

## This delivery

A clean public-safe implementation of the selected product interactions, rather than
an import of private prototype source history and research. It runs a browser reference
client against real SQL files and fixed non-sensitive data; real file apply/undo returns
actual Git diffs. Two unrelated configuration profiles exercise the same engine.

Retained interactions: clicked-ID trace; evidence-backed namespace/interval associations;
chronology versus arrival; prospective local edits without rewriting history; CTE and
scalar preview; latest-request scheduling; last-good historical results; scoped independent
checks; compare before apply; persistent drafts/evidence; uncluttered two-surface layout.

New foundations: registered file-backed projects, source and semantic context guards,
real Git-aware apply/undo, configuration-driven trace/replay, source-scoped metadata,
explicit Core and BigQuery adapter paths, and a tested stdio host bridge.

## Not represented as finished

- Native Zed/GPUI app compilation, packaging, full trace/live controls or target-Mac operation.
- BigQuery execution or intended-version Core compilation/test against the user's real project.
- DuckDB engine or GoogleSQL/local equivalence corpus; no dialect substitution.
- Enterprise privacy/PHI permission, retention, encryption and export policy.
- Arbitrary record/column lineage, general dbt project discovery, unregistered input closure.
- Full prior scenario-authoring UI, previous five-tool MCP surface, clinical examples,
  standalone HTML explainers, legacy metadata dashboard, or bulk issue importer.
- Editor feature parity such as full LSP, multi-cursor and project-wide source refactoring.

These omissions are deliberate and explicit; the new test count is not a claim that the
old 158-test implementation was imported or that every earlier feature remains available.
Existing private archives retain their own histories. The public repository must never
include those histories merely to make a continuity claim.

## Acceptance gates before calling this the daily native tool

1. Pin, typecheck and launch the native host on an Apple Silicon Mac; isolate name/data/updater.
2. Bind real buffers to saved/dirty dbt source identity, compile via the intended Core version.
3. Execute bounded approved non-sensitive BigQuery tests and retain actual job receipts.
4. Verify a registered real trace and dependency-sufficient snapshot, then an unrelated profile.
5. Port the two-surface interaction with actual focus, stale state and request-race tests.
6. Verify source edits, controlled rollback, independent negative controls and consumer uncertainty.
7. Conduct an actual user task and interruption/resume session, not a scripted feature count.

No prototype test can replace those real-environment checks. Blocked or unverified is an
acceptable status; a synthetic response is not a replacement for a cloud or native result.
